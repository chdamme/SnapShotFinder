Comments: automatic drafts and XMP

Each photo can contain one comment in each tile (01, 03, 04), up to 1,024 UTF-8 bytes per comment. Text, reference point, box position, photo zoom/pan and map views are saved automatically as browser drafts. Drafts are tied to the complete file contents, not to the name or row number. Reopening the same photo in the same browser restores its draft. Different exported JPG contents have their own drafts.

Save comments uses one operation for all photos concerned. With direct folder access it updates changed source JPGs, including those hidden by a filter. Without direct folder access, it downloads a complete copy of ALL loaded photos, whether changed, unchanged, commented or filtered out. In Chrome and other browsers with writable file access, Save comments updates the loaded source JPGs after you grant access to their source folder. The picker starts at the photo handle when available; an authorised source folder or file handle is reused. Only the selected source JPGs are changed, not other folder contents. JPEG pixels, EXIF, colour profiles and unrelated supported XMP are preserved. The committed file is read back before showing green. Externally changed sources are not overwritten. Other image formats can be exported as JPG copies using More → Download all photos (ZIP copy). Without direct folder writing (including Firefox), one Copy ZIP is downloaded with all loaded photos in a common folder. Extract it to obtain the complete photo folder. Unchanged files retain their bytes and original format; edited non-JPGs become JPG copies. A known common source-folder name is used; otherwise a dated Photos name is used. No viewer is included. A failed file stops the whole copy rather than silently omitting a photo. More → Download all photos (ZIP copy) is available in every browser.

Orange triangle: changes are not yet confirmed in a saved JPG. Green check in a circle: the current comment and view match XMP read from the loaded JPG, or from a saved copy that was written and read back. Red triangle: unsaved changes could not be secured in the browser. A failed disk save keeps orange when the browser draft is safe; the error is explained separately. The small symbol is directly before Comment in each comment box. Click or hover for details. Each tile is checked separately.

A normal download does not report its completion to this page. Clicking Save comments or ZIP therefore never proves that the file was saved. The existing edits stay orange (or red if browser storage has failed). Reopening the saved JPGs shows green. Optionally, use More → Verify saved ZIP / JPGs… to read back one completed ZIP or several JPGs from a recent export in this tab. One ZIP selection checks the entire batch, without replacing the currently open photos. Newer edits remain orange. Cancelling, denying access or preparing a file never turns an unverified comment green.

ZIP shares the filtered photos with the viewer and writes current XMP into every exported JPG. Save comments writes XMP into authorised source JPGs without recompressing their image data. Without direct access it offers one complete photo-copy ZIP instead, including unedited and filtered-out photos. The ZIP button still uses the filter and includes the viewer. Map coordinates and zoom are in XMP, but offline map images remain separate ZIP assets. Renaming or mixing exported JPGs does not detach their comments. Advanced JSON backup/import remains under More. Browser drafts are not a permanent backup: clearing browser data, private windows and browser storage failures can remove them.

From photo to location

Open or drop photos. SnapShotFinder reads their embedded EXIF GPS data, numbers the files in natural filename order, and places matching markers on two Geoportail maps. Select a row or a marker to view that photo. Arrow keys move between photos.

Folder viewer

Open or drop a photo, select it, then enable Folder viewer. Only photo files directly in its source folder are included; documents, sidecars, videos and subfolders are excluded. Where supported, Open photos and drag-and-drop retain a read-only file handle. The folder dialog uses that reference handle as its start location, without claiming to know an absolute path. An already granted and verified source folder is reused without another selection dialog. File permission alone does not grant access to neighbouring photos.

The regular file picker does not reveal a usable path, and its starting folder cannot be set by this page. In those browsers, choose the reference photo’s folder once and confirm its source. Previously selected folder lists remain available during this page session, including after a new photo import. When the new reference photo matches a saved list by name and contents, Folder viewer offers to reuse it after your explicit source confirmation. Matching names or contents alone are never proof of the source. Choose folder… instead to select another folder or obtain a fresh list. A saved list does not include photos added later and is not a live folder watch.

Repeated toggles reuse an already confirmed choice without another source question. A technical failure of the native folder picker offers an alternative folder picker with a fresh button click. Cancelling or refusing browser access does not open a replacement picker. Switch off to restore the original selection and numbering. A new photo import ends the viewer and never loads other folder photos automatically. Clear removes all remembered folder lists, associations and handles from this page; reloading or closing it also ends the session. Reading photos never changes their files. Save comments can explicitly update XMP in authorised source JPGs. ZIP writes comments into new JPG copies and leaves source files unchanged.

Filter photos with comments

With comments only keeps photos with at least one non-empty comment in Tile 01, 03 or 04. It combines with the text search and applies to the data table, Timeline, previous/next navigation, ZIP and Download JSON backup. Empty text boxes and saved zoom/map views alone do not count. The current preview stays open while you edit; filtering does not delete any photo or comment.

Saved comments are checked for every loaded photo, including photos not yet selected. ZIP and Download JSON backup wait until that check finishes. Adding, restoring, clearing or deleting a comment updates the filtered selection. Uncheck the option to show all photos admitted by the text search again. Clear or loading a new photo selection resets both filters. CSV retains its existing behaviour: all loaded photos are included.

Comments on photos and maps

Choose a photo, press + Comment in Tile 01, 03 or 04, then click the place you want to describe and type. Each tile has one comment, up to 1,024 UTF-8 bytes; the counter includes multi-byte characters. The button changes to Edit comment when a comment exists. Drag the green dot to move the reference point. Drag the small Comment handle to move the text box, or its lower-right corner to change its width. The box points toward its dot; the curved leader stays outside its own text box. Use × to delete a comment. Escape cancels placement or a drag; arrow keys move a focused dot or box handle.

Comments belong to the selected photo. Image points stay attached to image pixels, and map points to geographic coordinates. Photo zoom and pan, independent map views, and the Link maps setting are remembered per photo. When a point is outside the current view, its text box says so; the reference point is never silently moved to a different place.

Zoom and move a photo

Use + / − or the mouse wheel to zoom in Tile 01. Drag the enlarged photo with the left mouse button. On a phone or tablet, spread or pinch two fingers to zoom, then drag with one finger to move the enlarged photo. At 100%, a one-finger swipe scrolls the page normally. Fit shows the complete photo again; 100% means fitted to the tile, not original pixel size. Double-click or double-tap toggles between a closer view and Fit. Zoom ranges from 100% to 800%. Each photo remembers its zoom and position. No image file or metadata is changed.

Keyboard: focus the photo, then use + / − to zoom, arrow keys to move an enlarged photo, and 0 or Escape to fit. Outside the enlarged preview, left/right arrow keys still change photos. Printed output shows the complete photo; comment reference points are recalculated for that view.

Save the current screen

Screenshot freezes the visible SnapShotFinder page when you press the button, including the selected photo, its zoom and position, the active data tab, the table scroll position and the visible map layers. The preview offers Download PNG and Download PDF. Both contain the same frozen view; the PDF uses a single page with the screen's aspect ratio, not a rearranged A4 report. On phones, only the visible portion of the page is included. Files are created locally; no screen-sharing permission or photo upload is needed.

Some map servers or browsers prevent exporting map pixels. In that case, the preview keeps the frozen map canvases and offers Save as PDF / Print instead. Choose Save as PDF in your browser, enable background graphics, disable browser headers/footers and use no margins. The browser or printer may scale the view to its selected paper size. This fallback does not bypass browser security and does not silently omit a protected map.

Timeline

Timeline lists photos with valid GPS and an EXIF capture time, oldest first, while preserving their original numbers. DateTimeOriginal is preferred; DateTimeDigitized is the fallback. Blue arrows connect consecutive listed photos; time is shown above each connection and distance below it. With three or more photos, a dashed orange arrow also connects the first photo to the last. Its direct distance is not added to the cumulative distance. Leaving Timeline removes these extra connections. Search filters apply to both the Timeline table and its arrows.

No GPS data?

A photo can still be previewed without GPS data. The program does not guess its location or analyse landmarks. Enable location tagging in your camera before taking a photo. Use original files: messaging apps, image editing or screenshots may remove metadata.

Supported files

The built-in reader handles standard EXIF metadata in JPEG, PNG, TIFF and WebP. HEIC/HEIF, AVIF, RAW, BigTIFF and XMP-only GPS coordinates are not read in this version. Export such files to JPEG with metadata preserved. TIFF preview depends on your browser; coordinates can still be read when a preview is unavailable.

Coordinates and addresses

Latitude and longitude are WGS84. X/Y LUREF are metres in EPSG:2169, calculated when the Geoportail projection library is available and only within the Luxembourg region. Decimal places are display formatting, not an accuracy guarantee. “Direction” is the camera's EXIF compass heading; T means true north and M means magnetic north.

An address result is the nearest known Luxembourg address, not proof that the camera was at that property. Its straight-line distance is shown separately. The nearest Luxembourg road is determined independently, with the shortest distance to its digitised centreline (perpendicular projection where possible, otherwise the segment endpoint). No route distance, road access or exact camera address is inferred. Photos outside Luxembourg still show the nearest entries in these Luxembourg-only registers. A numbered marker is the camera location, not necessarily the location of the photographed object. A group-centre cross is only a map reference.

Registers and background downloads

This Slim HTML contains the program but no address, road or CFL registers. At startup, saved registers are reused and missing registers download from the official Luxembourg data services in the background. Each completed, validated register becomes available immediately. Existing photos are automatically updated as more data arrives. Address points and road axes remain independent nearest matches.

Until local address data is ready, Geoportail reverse geocoding supplies addresses. Requests are queued, identical coordinates share a request, and local results take over when the register is ready. Road and CFL results appear after their respective registers finish downloading. If a service is unavailable, the app continues with whatever data is available and shows a status message instead of a dialog.

Each successful download is saved immediately in this browser when storage is allowed. Storage failure does not prevent using the registers for the current session. Private browsing, browser-data deletion, storage limits or restrictions can require another download on the next visit. Local HTML files may have browser-dependent storage boundaries; moving or renaming one can affect reuse. The original HTML file on disk is never silently overwritten.

After seven days since the last successful complete check, the sources are checked again in the background. Unchanged registers are reused. Update registers forces an immediate download of all three registers. Existing data stays available until its replacement is complete and valid. Interrupted updates are retried with a delay when online. Publisher dates and geometry dates are kept distinct from download dates.

Download Slim HTML always creates another small program file with no registers, photos or browser data embedded. The recipient loads their own register copies. Saving the program does not depend on a finished register download.

Privacy and internet access

Your photos are read locally and are never uploaded or modified. While the address register is missing, the photo GPS coordinates are sent to Geoportail for address lookup. Once it is ready, address comparisons run locally. Roads and CFL/PK are calculated locally after the relevant registers have loaded. Register downloads contact the official data services. Map requests reveal the viewed area to Geoportail. Maps and LUREF conversion depend on the online mapping library. Clear removes loaded photos and folder handles; saved registers remain. A failed map connection does not stop photo reading or available local searches.

Geoportail's API documentation requires ACT access approval for a hosting domain. A blank or denied map can therefore be a domain-permission, network or provider issue.

CFL lines and PK

In Addresses, the three columns after the roads show every distinct downloaded CFL route whose shortest horizontal distance to the photo GPS point is at most 250 metres. Each route has its own aligned entry with its designation and name, distance to the digitised axis, and PK at that projection. Entries are sorted by increasing distance. The 250 m limit is inclusive and tested before rounding. Overlapping or coincident routes remain separate; each route appears only once per photo. If none qualifies, the table explicitly displays “No CFL line ≤ 250 m”. PK is interpolated along the route between official hectometre references, not inferred from distance to a station or to a kilometre marker. At vertices or line ends, the nearest vertex is used. A dash in PK means there are no suitable bracketing references, a reference gap, conflicting references or a kilometre discontinuity; no PK is extrapolated. The route and its distance remain visible even when its PK is unavailable. The filter searches all listed CFL routes and PKs. CSV contains one record per photo/route pair with numeric distances; a photo without any nearby line is retained once with blank CFL values.

The available source geometry is historical (27 March 2017). These geometries and kilometre references do not certify the current track layout. The source date is shown separately from the download date; checking for updates does not make historical data current. Current L-numbers are retained only where the RailPK snapshot records a Geoportail station-data match; other lines retain their explicitly marked historical IDs. All qualifying routes are displayed directly, not hidden in a tooltip or treated as a single ambiguous result. Hover over a route, distance or PK for its details. GPS uncertainty is not inferred from the number of displayed digits. These results are for orientation, not a safety authorisation or a survey.

CFL line geometry and hectometre references download together from the official KML sources. After downloading, CFL calculations run locally without a request per photo. Update registers includes CFL. Download Slim HTML includes the calculation code and source links; the register data is downloaded again by the recipient.

Sources: CFL railway lines; CFL hectometre references; Geoportail station data (line-ID matching in the RailPK snapshot). © CFL / data.public.lu — CC BY-SA 4.0. Adapted KML-to-JSON data and line-ID mapping retain this licence; compressed and integrated into SnapShotFinder. The ACT address and road datasets retain their separate CC0 licence.

One replacement file

All application code and styling are inside index.html. Your old java.js and stylesheet.css are no longer loaded. Geoportail supplies its mapping libraries online. CSV exports include all selected files, even those without GPS; a search filter does not limit the export.
